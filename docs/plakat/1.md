# LHRP — Lightweight Hierarchical Routing Protocol

**Autor:** Manuel Westermeier  •  Kategorie: Mathematik / Informatik

---

## Kurzfassung

LHRP ist ein leichtgewichtiges Forwarding-Protokoll für ressourcenbeschränkte Embedded-Netzwerke. Es nutzt strikt-hierarchische Adressen (präfixbasiert) kombiniert mit frei wählbaren physischen Verbindungen. Die Next-Hop-Entscheidung erfolgt lokal über einen **Match‑Index** (Prefix-Match minus Adressrest), wodurch Routing ohne globale Tabellen möglich ist.

---

## Motivation

* Mikrocontroller (z. B. ESP32) haben begrenzten Speicher und Rechenleistung.
* Klassische Protokolle (Link‑State, Distance‑Vector) sind zu aufwändig.
* Ziel: sehr geringer Metadaten‑Overhead, sichere Übertragung, robust in dynamischen Topologien.

---

## Idee & Topologie

* **Adressmodell:** Adressen sind Vektoren von Bytes: z. B. `{2,255,4,5}`. Jede Komponente ist ein Layer.
* **Logische Struktur:** Baumartige (hierarchische) Adressverteilung.
* **Physische Struktur:** Frei vernetzte Links (Shortcut-Links) erlauben Mesh‑ähnliche Verbindungen.
* **Regel:** Jede Node hat mindestens eine Verbindung zu ihrer Parent-Adresse (außer Root).

**Vorteile:** baumartige Routing-Eigenschaften (gerichtetes Auf-/Absteigen) plus verkürzende Shortcuts.

---

## Match‑Index (Routing-Entscheidung)

**Definition:**

* *positive* = Anzahl identischer Bytes vom Adressenanfang (längstes gemeinsames Präfix)
* *negative* = verbleibende Bytes der Next‑Hop‑Adresse (`nextHop.length - positive`)

**Formel:**

[ MatchIndex = positive - negative ]

**Interpretation:**

* großes positives Ergebnis → Next Hop ist tiefer (Child) → Abstieg
* negatives Ergebnis → Next Hop ist näher zur Root (Parent) → Aufstieg
* bei Gleichstand entscheidet die längere Adresse (fördert tieferes Routing)
* direkte Children dürfen nicht umgangen werden (Hierarchie‑Schutz)

---

## Implementierung (Kernlogik)

Visualisierung der Entscheidung:

* Prüfe, ob Ziel = eigene Adresse → lokale Zustellung
* Vergleiche MatchIndex aller Verbindungen → wähle höchsten
* Tie‑Break: längere Adresse gewinnt
* Sonderregeln: direkte Child‑Ziele und Schutz vor Rückwärtsrouting

**Hardware & Framework:** ESP32 (ESP‑NOW), Implementierung als C++ Library (PlatformIO / VSCode).

**Messwerte (Mittelwerte)**

| Algorithmus | Erfolg | avgHop | avgOps (Vergl.) |
| ----------: | :----: | :----: | :-------------: |
|    **LHRP** |  100%  | 12.392 |    **56.568**   |

|    Dijkstra |  100%  |  9.228 |     2718.384    |
|          A* |  100%  | 10.423 |     275.719     |

**Praktische Bedeutung:** LHRP erreicht vergleichbare Routing‑Werte bei deutlich geringerem lokaler Rechenaufwand pro Hop. LHRP bevorzugt in vielen Fällen zwar minimal mehr Hops als Dijkstra/BFS, reduziert dafür aber die Anzahl lokaler Operationen massiv.

## Zeitkomplexitäten — asymptotisch & praktisch

**LHRP (lokale Next‑Hop‑Entscheidung):**

* Pro Paket: vergleiche alle Verbindungen `d = deg(node)` mit Zieladresse Länge `L` → `O(d * L)` (Prefix‑Vergleich pro Verbindung)
* Typisch in Simulation: `d ≈ 2.44`, gemessene `avgOps ≈ 56.57` → geschätzte mittlere Adresslänge `L ≈ 56.568 / 2.44 ≈ 23.2` Bytes

**BFS:** `O(|V| + |E|)` pro Pfadsuche (keine Heuristik) → bei 2000 Nodes und ~ (nodes*avgDegree/2) Kanten sehr teuer. Entspricht gemessenen ~2718 Ops.

**Dijkstra (mit Min‑Heap):** `O((|E| + |V|) log |V|)` — Rechenintensiv bei großen Netzen, entspricht in Simulation ebenfalls ~2718 Ops.

**A*:** im besten Fall substanziell schneller als Dijkstra, im Worst‑Case gleich. Gemessene `avgOps ≈ 275.7` (deutlich weniger als BFS/Dijkstra, aber mehr als LHRP lokal).

**Fazit:** LHRP verlagert Komplexität in eine sehr schnelle, lokal auswertbare Heuristik: niedrige Rechenkosten, deterministisches, zyklusverminderndes Verhalten.

## Sicherheit & Robustheit

* AES‑GCM Verschlüsselung der Payloads (IV, Tag), Replay‑Schutz
* Kein globales Routing‑State → geringere Angriffsfläche durch manipulative Routing‑Tabellen
* Fail‑Checks verhindern Endlosschleifen bei fehlerhafter Hierarchie

### Anhang — Vollständiger relevanter Code

```cpp
#pragma once

#include <vector>
#include <algorithm>
#include "pocket.hpp"

#define LHRP_PIN_ERROR 255

using namespace std;

struct Match
{
    uint16_t positive;
    uint16_t negative;
};

inline Match match(const Address &connection, const Address &pocket)
{
    size_t minLen = min(connection.size(), pocket.size());
    Match m{0, 0};

    while (m.positive < minLen &&
           connection[m.positive] == pocket[m.positive])
        m.positive++;

    m.negative = connection.size() - m.positive;
    return m;
}

inline int matchIndex(const Match &m)
{
    return (int)m.positive - (int)m.negative;
}

inline bool eq(const Address &a1, const Address &a2)
{
    return a1.size() == a2.size() &&
           equal(a1.begin(), a1.end(), a2.begin());
}

inline bool isChildren(const Address &other, const Address &you)
{
    if (other.size() <= you.size())
        return false;

    for (size_t i = 0; i < you.size(); i++)
        if (other[i] != you[i])
            return false;

    return true;
}

struct Connection
{
    Address address;
    uint8_t pin;
};

struct Node
{
    vector<Connection> connections;
    Address you;

    uint8_t send(const Pocket &p)
    {
        if (eq(you, p.destAddress))
            return 0;

        if (connections.empty())
            return LHRP_PIN_ERROR;

        Connection *best = &connections[0];
        int bestIdx = matchIndex(match(best->address, p.destAddress));
        size_t bestLen = best->address.size();

        for (size_t i = 1; i < connections.size(); i++)
        {
            int idx = matchIndex(match(connections[i].address, p.destAddress));
            size_t len = connections[i].address.size();

            if (idx > bestIdx || (idx == bestIdx && len > bestLen))
            {
                best = &connections[i];
                bestIdx = idx;
                bestLen = len;
            }
        }

         // wen child nicht vorhanden ist
        bool directChild = isChildren(p.destAddress, you);
        int ownMatchIdx = matchIndex(match(you, p.destAddress));
        if (directChild && (!isChildren(best->address, you) || bestIdx < ownMatchIdx))
            return 0;

        // wenn parent nicht vorhanden ist
        if (bestIdx <= ownMatchIdx)
            return LHRP_PIN_ERROR;

        return best->pin;
    }
};
```
